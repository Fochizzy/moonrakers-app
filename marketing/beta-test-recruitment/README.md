## Practical posting notes

- Replace `[BETA LINK]` before publishing.
- Lead with the benefit, not the feature count.
- Ask for a specific tester profile: regular groups willing to test during real sessions and report friction.
- Keep “beta” visible so rough edges feel like an invitation to contribute, not a broken promise.
- Do not place small text over the screenshots; let the real interface be the evidence.
- Before publishing, confirm that the people represented by the visible player names and handles are comfortable appearing in public promotional material.
- If this is not an officially affiliated product, add a plain “unofficial companion app” disclosure wherever you publish the beta invitation.
